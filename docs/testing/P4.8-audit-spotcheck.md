# P4.8 — audit trail spot-check (T18 load run)

**Result: PASS** — run on 2026-11-11 against database `kagaz_rt`, which holds the 200-order T18 load run of 2026-11-07 ([T18-load-run.md](T18-load-run.md)).

## What "complete" means

For each order:

1. **Event chain:** the first `OrderEvent` is `∅ → DRAFT`, each next event starts at the status the previous one ended in, and the last event's `to_status` equals the order's current status.
2. **Audit:** every transition made by a human or device actor (`DEVICE`, `STAFF`, `ADMIN`) has an `audit_logs` row for the same order, actor type and actor id, written within 1 s of the event (the state machine writes both in the same DB transaction). `CUSTOMER`/`SYSTEM` transitions (create, submit, payment verified) need no audit row.
3. **Payment:** paid orders have a captured payment; unpaid orders have none.

## Note

The load run predates [ADR-002](../decisions/ADR-002-daily-pickup-number.md): READY was a device "Mark Ready" action (`order.ready` audit) and collection used `pickup.verified`. Under ADR-002, `PRINTING → READY_FOR_PICKUP` is a SYSTEM transition and needs no audit row; the check above handles that unchanged because it only requires audit rows for `DEVICE`/`STAFF`/`ADMIN` events.
